# Figure Design Review

这是渲染后的视觉和科学表达审查流程。先读项目根目录的 [AGENTS.md](../../../AGENTS.md)，并尽可能打开实际 PNG；只读源码或只看自动分数不能代替视觉审查。

## 适用场景

- 图片已经生成，需要检查论文插入尺寸下的可读性和排版。
- 多张图需要统一字体、色彩、线宽、面板标签和图例语言。
- 现有图表需要在源码层面修复遮挡、裁切、误导性层级或导出问题。

## 不适用场景

- 从原始数据开始设计新图时，主流程使用 `modern-scientific-figure`。
- 需要证明收敛、误差、支配关系或不确定性方法时，同时使用 `algorithm-visualization`。
- 只有图片分类、索引或设计笔记时，使用 `figure-reference-manager`。

## 审查顺序

1. 记录目标插入尺寸、输出文件和对应 `plot.py`；确认图片与源码来自同一生成版本。
2. 打开 PNG，按原始尺寸和预计论文尺寸各看一次。必要时同时检查 SVG/PDF 是否存在且不是空白。
3. 按数据表达、布局、文字、颜色、图例、轴线、标记、注释和导出逐项检查；每个问题写出位置、影响和可执行修改。
4. 先修复科学表达、裁切、重叠和可读性，再处理颜色、留白和装饰。辅助信息应弱于主要结果，但不能消失。
5. 修改 `plot.py` 或 `config.py`，重新运行源码并重新打开图片。不要直接修补 PNG 作为最终版本。
6. 记录已经检查的文件、发现的问题、修复动作和仍未验证的项目。

## 可执行问题格式

使用“位置 — 影响 — 修改”记录，例如：`右上图例 — 遮挡测试点 — 移到图外并收紧右边距，再以缩小尺寸复查`。不要只写“美化排版”或“图片很漂亮”。

## 审查契约

审查结论必须能回到实际图片和源码。交付时保留修改后的源码、配置和图片；若当前环境无法打开图片，明确标记视觉检查为未验证，不得声称已通过。

## 常见错误

| 错误 | 修复 |
| --- | --- |
| 只看代码不看渲染结果 | 使用本地图片查看工具或实际图片预览。 |
| 只给主观评分 | 写出具体元素、位置、影响和修改动作。 |
| 为了留白删掉单位或关键标注 | 保留科学语义，优先调整布局和字号。 |
| 只改最终位图 | 回到生成源码，重新导出全部格式。 |
